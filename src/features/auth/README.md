# 인증 구현 상태

## 구현 범위

- 일반 유저/기사님 로그인·가입 UI, 입력 검증, 오류 focus, 반응형
- `auth.api.ts` → 팀 백엔드 `/auth` API 연결, TanStack Query 세션 조회
- 이메일 가입/로그인 성공 후 홈 이동, GNB 사용자 정보와 로그아웃 연결
- 액세스 만료 시 refresh, HttpOnly 쿠키, 탭 간 Web Locks 직렬화
- SNS 버튼 → 서버의 공급자 인증 URL → `/auth/callback` → 실제 세션 확인
- 고객/기사 레이아웃에서 로그인·역할·프로필 등록 안내

프로필 등록 페이지와 기타 견적 페이지는 다른 담당 영역이며 현재 빈 파일입니다. 미등록 사용자는 인증 후 홈으로 이동합니다. 프로필 완료는 백엔드 프로필 구현에서 갱신해야 하며 클라이언트가 변경할 수 없습니다.

## 로컬 실행

FE `.env.local`의 `NEXT_PUBLIC_API_URL`은 로컬 BE 주소를 가리킵니다(현재 http://localhost:4000).
BE의 `.env.example`, `docs/auth-implementation.md`와 `docs/auth-local-testing.md`를 참고해 DB 마이그레이션 후 API를 실행합니다. 비밀키는 FE에 넣지 않습니다.

## OAuth 준비 상태

Google/Kakao/Naver의 코드 교환 및 콜백 처리는 구현했습니다. 2026-09-07 로컬에서 Naver/Kakao 실제 동의 후 홈 복귀와 새로고침 세션 유지를 확인했습니다. Google은 콘솔의 클라이언트 생성 화면 로드 오류로 자격증명 발급과 실제 로그인 검증이 남았습니다. 미설정 버튼은 안내 메시지를 표시합니다. 공급자 모의 응답 테스트와 실제 SNS 로그인 완료를 혼동하지 않습니다.

## 검증

- 두 역할의 실제 DB/HTTP 가입·로그인·로그아웃과 브라우저 새로고침 세션 유지
- 잘못된 비밀번호, 중복 이메일, 역할 불일치, 토큰 회전/재사용/만료, 로그아웃 경합
- OAuth state 바인딩과 재사용 거부, 공급자 모의 응답 변환
- 1440/744/375px 화면과 320px 오류 문구·역할 전환 검사
- 변경 범위 ESLint 통과. FE 전체 타입 검사/빌드는 기존 빈 page.tsx와 modal-test 문제로 통과하지 못합니다.
